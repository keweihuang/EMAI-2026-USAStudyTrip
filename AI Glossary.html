How to use this glossary

The objective is not to memorize technical jargon, but to ask sharper questions during company visits and translate AI concepts into leadership decisions. Click any category below to expand its terms.

Before each visit

  • Open the relevant category, then review 10–15 terms that match the session topic.
  • Ask: “Is this concept a technology capability, a data requirement, an operating model, or a risk-control issue?”
  • Prepare one business question: adoption, ROI, talent, governance, or competitive advantage.

During Q&A

  • Move from “What is the technology?” to “What decision does it improve, and how is success measured?”
  • Probe the implementation layer: data readiness, model evaluation, change management, security, and accountability.
  • Capture reusable patterns: build/buy/partner choices, human-in-the-loop design, and responsible scaling.

Core AI

Algorithm

An algorithm is a structured set of instructions for transforming inputs into outputs. In AI, algorithms define how models learn from data, generate predictions, or optimize decisions.

Core AI

Artificial Intelligence (AI)

AI refers to computer systems that perform tasks requiring human-like capabilities such as perception, reasoning, language understanding, prediction, or decision support. In executive discussions, AI is best treated as a portfolio of capabilities rather than a single technology.

Core AI

Dataset

A dataset is a collection of examples used for training, testing, validation, or monitoring. Executive questions should focus on representativeness, permissions, freshness, quality, and whether the dataset reflects the target population.

Reference ↗
Core AI

Deep Learning

Deep learning uses multi-layer neural networks to learn complex patterns from large datasets such as text, images, audio, or transactions. It powers many modern breakthroughs in language models, computer vision, and speech recognition.

Reference ↗
Core AI

Feature

A feature is an input variable used by a model, such as price, clicks, customer tenure, or text embeddings. Good feature design connects raw data to the business signal the model needs to learn.

Reference ↗
Core AI

Inference

Inference is the use of a trained model to generate an output for a new input, such as classifying a customer request or drafting a response. In business systems, inference cost, latency, and reliability often determine whether an AI use case can scale.

Reference ↗
Core AI

Label

A label is the known answer used to train or evaluate a supervised learning model, such as default/no default or churn/no churn. Label quality is crucial because a model can only learn what the organization defines and records well.

Reference ↗
Core AI

Machine Learning (ML)

Machine learning is a subset of AI in which models learn patterns from data instead of being explicitly programmed with fixed rules. It is the engine behind many prediction, classification, personalization, and anomaly-detection systems.

Reference ↗
Core AI

Model

A model is the learned mathematical or computational representation produced by training on data. Executives should ask what the model predicts, how it was trained, and how its performance is monitored in production.

Reference ↗
Core AI

Neural Network

A neural network is a model architecture inspired by interconnected nodes that transform inputs through layers. Neural networks are the foundation for deep learning systems in language, vision, speech, and recommendation.

Reference ↗
Core AI

Reinforcement Learning

Reinforcement learning trains an agent to choose actions by receiving rewards or penalties from an environment. It is powerful in simulations and control problems, but harder to apply when the real-world environment cannot be safely or repeatedly explored.

Reference ↗
Core AI

Supervised Learning

Supervised learning trains models using examples with known labels. It is common in use cases such as credit scoring, fraud detection, churn prediction, and quality inspection.

Reference ↗
Core AI

Training

Training is the process of adjusting a model’s parameters so it can perform a task on examples. Strong training depends on relevant data, clear objectives, appropriate evaluation, and safeguards against overfitting or bias.

Reference ↗
Core AI

Transfer Learning

Transfer learning reuses knowledge learned from one task or dataset to improve performance on another task. It is a key reason foundation models can be adapted efficiently for enterprise applications.

Reference ↗
Core AI

Unsupervised Learning

Unsupervised learning finds patterns in data without predefined labels, such as customer segments or clusters of similar documents. It is useful when organizations want discovery, grouping, or anomaly signals rather than direct prediction.

Generative AI

Agent Orchestration

Agent orchestration coordinates multiple model calls, tools, or specialized agents to complete a complex workflow. It is important when tasks require planning, routing, verification, and handoffs across systems.

Reference ↗
Generative AI

Agent2Agent (A2A)

A2A is an emerging open protocol for letting AI agents from different vendors and platforms communicate and collaborate on shared tasks. It addresses a key enterprise concern: avoiding lock-in to a single vendor’s agent ecosystem.

Reference ↗
Generative AI

Agentic AI

Agentic AI refers to AI systems that can plan, coordinate subtasks, use tools, and adapt over multiple steps. It promises productivity gains but requires stronger guardrails, permissions, monitoring, and escalation paths.

Reference ↗
Generative AI

AI Agent

An AI agent is software that uses a model to reason about a goal, choose steps, call tools, and act on behalf of a user or workflow. The key question is not only what it can generate, but what actions it is allowed to take.

Reference ↗
Generative AI

Chatbot

A chatbot is a conversational interface that responds to user messages through rules, retrieval, AI models, or a combination of these. Modern chatbots increasingly combine LLMs with enterprise data and workflow tools.

Reference ↗
Generative AI

Context Window

The context window is the maximum amount of input and conversation history a model can use when generating a response. A larger context window helps with long documents, but does not automatically guarantee better reasoning or accuracy.

Reference ↗
Generative AI

Diffusion Model

A diffusion model generates data by learning to reverse a process that gradually adds noise. It is widely associated with high-quality image generation and other media synthesis tasks.

Reference ↗
Generative AI

Fine-Tuning

Fine-tuning adapts a pre-trained model using additional examples for a specific task, style, domain, or policy. It can improve consistency, but it requires high-quality data and should not replace retrieval or governance when the issue is missing knowledge.

Reference ↗
Generative AI

Foundation Model

A foundation model is a large model trained on broad data that can be adapted to many downstream tasks. Its value comes from general-purpose capability, but adoption requires careful tuning, governance, and evaluation.

Reference ↗
Generative AI

Generative AI

Generative AI creates new content such as text, images, audio, video, code, or structured analysis from learned patterns. It shifts AI from pure prediction toward content creation, workflow assistance, and human productivity augmentation.

Reference ↗
Generative AI

Large Language Model (LLM)

An LLM is a model trained on large text and code corpora to understand, generate, summarize, translate, or reason over language. LLMs are powerful interfaces to knowledge work, but they still need grounding, evaluation, and controls.

Reference ↗
Generative AI

Model Context Protocol (MCP)

MCP is an open standard, originated by Anthropic, that lets AI assistants connect to data sources, tools, and enterprise systems through a uniform interface. It is becoming an industry standard adopted by Salesforce, Box, Cisco, and many others to reduce one-off integrations.

Reference ↗
Generative AI

Multimodal AI

Multimodal AI can process or generate more than one type of data, such as text, image, audio, video, tables, or sensor signals. It is central to enterprise use cases that combine documents, dashboards, calls, diagrams, and real-world observations.

Reference ↗
Generative AI

Prompt

A prompt is the instruction, question, data, or context given to a generative AI system. Better prompts clarify role, task, constraints, examples, output format, and evaluation criteria.

Reference ↗
Generative AI

Prompt Engineering

Prompt engineering is the practice of designing instructions and context so a model produces useful outputs. In enterprise settings, prompts often become reusable workflow assets embedded in products, copilots, or agent systems.

Reference ↗
Generative AI

Small Language Model (SLM)

An SLM is a smaller language model designed for lower cost, lower latency, privacy-sensitive deployment, or task-specific performance. SLMs can be attractive when an enterprise needs reliable execution rather than maximum generality.

Reference ↗
Generative AI

Token

A token is a unit of text or data that a language model processes, often a word fragment rather than a full word. Token limits influence context length, cost, speed, and how much information a model can consider at once.

Reference ↗
Generative AI

Tool Use / Function Calling

Tool use lets an AI system call external software, databases, calculators, APIs, or workflow actions in a structured way. This turns a model from a passive text generator into a controlled interface for enterprise execution.

Reference ↗
Generative AI

Transformer

A transformer is a neural network architecture that uses attention mechanisms to process sequences such as text or code. Transformers are the backbone of most modern large language models and many multimodal AI systems.

Reference ↗
Generative AI

Vibe Coding

Vibe coding describes a workflow where developers describe intent in natural language and let AI tools generate or modify code, with humans steering rather than writing line by line. It is reshaping software engineering productivity and team composition.

Data & Knowledge

A/B Testing

A/B testing compares two versions of a product, message, model, or workflow using randomized exposure. It is a core method for measuring whether AI changes actually improve user or business outcomes.

Reference ↗
Data & Knowledge

Data as a Strategic Asset

Data becomes strategic when it improves decisions, differentiates products, compounds learning, or creates defensible advantage. Treating data as an asset requires ownership, governance, quality management, access design, and value measurement.

Reference ↗
Data & Knowledge

Data Governance

Data governance defines decision rights, standards, controls, lineage, privacy, quality, and accountability for data. AI governance is weak when data governance is weak.

Reference ↗
Data & Knowledge

Data Lakehouse

A data lakehouse combines flexible data lake storage with warehouse-style management and analytics capabilities. It is often used to support AI teams that need both raw data and governed, queryable datasets.

Reference ↗
Data & Knowledge

Data Lineage

Data lineage tracks where data came from, how it changed, and where it is used. It is essential for auditability, debugging, regulatory review, and understanding AI outputs.

Reference ↗
Data & Knowledge

Data Pipeline / ETL

A data pipeline moves, transforms, cleans, and delivers data for analytics or AI systems. ETL stands for extract, transform, load, and is often a hidden determinant of AI project success.

Reference ↗
Data & Knowledge

Data Quality

Data quality refers to whether data is accurate, complete, consistent, timely, relevant, and fit for purpose. Poor data quality can create misleading AI outputs even when the model architecture is advanced.

Reference ↗
Data & Knowledge

Decision Intelligence

Decision intelligence combines data, models, workflows, and human judgment to improve decisions. It asks not only what the model predicts, but how the prediction changes action and accountability.

Reference ↗
Data & Knowledge

Embedding

An embedding is a numerical representation of text, images, users, products, or documents in a vector space. Similar meanings or objects tend to be close together, enabling semantic search, clustering, recommendation, and retrieval.

Reference ↗
Data & Knowledge

Experimentation

Experimentation is the disciplined testing of hypotheses using controlled comparisons, pilots, or randomized trials. AI leaders need experimentation to separate real value from demos and hype.

Reference ↗
Data & Knowledge

Knowledge Graph

A knowledge graph represents entities and relationships, such as companies, products, executives, suppliers, and risks. It can improve search, reasoning, recommendation, and explainability by making relationships explicit.

Reference ↗
Data & Knowledge

Metadata

Metadata is data about data, such as source, owner, format, permissions, lineage, and update frequency. It helps teams discover, trust, govern, and reuse data assets for AI.

Reference ↗
Data & Knowledge

Predictive Analytics

Predictive analytics uses data and models to estimate what is likely to happen, such as churn, demand, risk, or maintenance failure. Its value depends on whether predictions are actionable in a business process.

Reference ↗
Data & Knowledge

Prescriptive Analytics

Prescriptive analytics recommends actions based on predicted outcomes, constraints, and objectives. It moves analytics from insight toward decision support and operational optimization.

Reference ↗
Data & Knowledge

Retrieval-Augmented Generation (RAG)

RAG connects a generative model to external knowledge sources so responses can be grounded in documents, databases, or current information. It is a common architecture for enterprise chatbots and knowledge assistants because it reduces reliance on model memory alone.

Reference ↗
Data & Knowledge

Semantic Search

Semantic search retrieves information based on meaning rather than exact keyword matching. It helps users find relevant documents, policies, cases, or product information even when they use different wording.

Reference ↗
Data & Knowledge

Synthetic Data

Synthetic data is artificially generated data designed to resemble real data while supporting testing, training, privacy, or rare-case simulation. It is useful but must be validated carefully because synthetic patterns can mislead models.

Reference ↗
Data & Knowledge

Vector Database

A vector database stores and searches embeddings efficiently, usually by similarity. It is often used in retrieval-augmented generation, document search, recommendation, and knowledge discovery systems.

Trust & Risk

Accountability

Accountability means identifiable people or teams are responsible for AI design, deployment, monitoring, and consequences. It prevents responsibility from disappearing behind the model or vendor.

Reference ↗
Trust & Risk

AI Ethics

AI ethics examines whether AI systems are designed and used in ways that respect human values, rights, fairness, and societal impact. It becomes practical when translated into product requirements, review processes, and measurable controls.

Reference ↗
Trust & Risk

AI Governance

AI governance is the structure of policies, roles, processes, controls, and oversight used to manage AI benefits and risks. It should cover data, models, vendors, use cases, monitoring, escalation, and accountability.

Reference ↗
Trust & Risk

AI Safety

AI safety focuses on preventing harmful, unreliable, or unintended behavior from AI systems. In enterprises, safety includes technical safeguards, policy constraints, incident response, and human escalation.

Reference ↗
Trust & Risk

Alignment

Alignment refers to making AI systems behave according to intended goals, constraints, and human values. In business deployment, alignment includes matching model behavior to company policy, user needs, and risk appetite.

Reference ↗
Trust & Risk

Bias

Bias is a systematic tendency in data, design, or model behavior that can produce distorted or unfair outcomes. Bias can enter through historical data, measurement choices, labels, sampling, objectives, or deployment context.

Reference ↗
Trust & Risk

Content Credentials (C2PA)

C2PA is an open technical standard for cryptographically signing media with origin and edit history, supported by Adobe, Microsoft, and many publishers. It is becoming a key tool for verifying authenticity in an era of generative content.

Reference ↗
Trust & Risk

Differential Privacy

Differential privacy is a mathematical approach that limits what can be learned about any individual from a dataset or model output. It is one tool for balancing data utility with privacy protection.

Reference ↗
Trust & Risk

EU AI Act

The EU AI Act is a risk-tiered regulation classifying AI systems as unacceptable, high-risk, limited-risk, or minimal-risk, with corresponding obligations. It has extraterritorial reach, affecting any organization deploying AI services to EU users.

Reference ↗
Trust & Risk

Explainability

Explainability is the ability to provide understandable reasons for an AI output or behavior. The right explanation depends on the audience: user, manager, engineer, regulator, or affected individual.

Reference ↗
Trust & Risk

Fairness

Fairness concerns whether an AI system treats individuals or groups appropriately under the context and purpose of use. It often requires both quantitative metrics and human judgment about acceptable trade-offs.

Reference ↗
Trust & Risk

Grounding

Grounding means tying model outputs to reliable source material, tools, or verified data. It helps reduce hallucination risk and gives users a basis for checking important claims.

Reference ↗
Trust & Risk

Guardrails

Guardrails are technical and procedural controls that constrain AI behavior, such as policy filters, retrieval boundaries, validation checks, permissions, and human review. They reduce risk but do not eliminate the need for evaluation and monitoring.

Reference ↗
Trust & Risk

Hallucination

A hallucination is an AI-generated statement that sounds plausible but is false, unsupported, or not grounded in the provided sources. Hallucinations are especially risky in legal, financial, medical, compliance, and customer-facing settings.

Reference ↗
Trust & Risk

Model Risk Management

Model risk management identifies, assesses, controls, and monitors risks arising from model errors, misuse, drift, or inappropriate assumptions. For AI, it must include both statistical performance and sociotechnical impact.

Reference ↗
Trust & Risk

NIST AI RMF

The NIST AI Risk Management Framework is a voluntary US standard for governing, mapping, measuring, and managing AI risks. It is widely referenced by enterprises and is increasingly used as the practical baseline for responsible-AI programs.

Reference ↗
Trust & Risk

Privacy

Privacy in AI concerns how personal or sensitive information is collected, used, stored, inferred, shared, and protected. AI systems can create privacy risks even when they use derived features or generated outputs.

Reference ↗
Trust & Risk

Red Teaming

Red teaming tests an AI system by deliberately probing for failures, misuse, unsafe outputs, leakage, or security weaknesses. It should be part of pre-launch review and ongoing monitoring for high-impact systems.

Reference ↗
Trust & Risk

Responsible AI

Responsible AI is the practice of designing, building, deploying, and governing AI in ways that are safe, fair, accountable, privacy-aware, and beneficial. It is an operating discipline rather than a public-relations statement.

Reference ↗
Trust & Risk

Robustness

Robustness is the ability of an AI system to maintain acceptable performance under noise, distribution shifts, adversarial inputs, or changing conditions. It is a key attribute for systems used in dynamic business environments.

Reference ↗
Trust & Risk

Transparency

Transparency means relevant stakeholders can understand that AI is being used, what it is intended to do, and how key decisions are made or reviewed. Transparency supports trust, accountability, and user choice.

Reference ↗
Trust & Risk

Trustworthy AI

Trustworthy AI emphasizes characteristics such as validity, reliability, safety, security, resilience, accountability, transparency, explainability, privacy, and fairness. These qualities must be engineered and governed throughout the lifecycle.

Reference ↗
Trust & Risk

Watermarking (SynthID)

Watermarking embeds invisible signals into AI-generated text, images, audio, or video so that they can later be identified as machine-generated. Google’s SynthID is one prominent example, used to support content provenance and combat misinformation.

Cybersecurity14 terms
Cybersecurity

Access Control

Access control restricts who or what can view data, call tools, run models, or approve AI actions. It is especially important when LLMs are connected to internal documents, customer records, or workflow systems.

Reference ↗
Cybersecurity

Adversarial Machine Learning

Adversarial machine learning studies attacks that manipulate inputs, data, or models to cause incorrect behavior. Examples include subtly altered images, poisoned data, evasion attacks, and prompt-based manipulation.

Reference ↗
Cybersecurity

Cyber Resilience

Cyber resilience is the ability to withstand, recover from, and adapt to cyber disruptions while maintaining essential operations. AI can strengthen resilience through detection and automation, but it can also expand the attack surface.

Reference ↗
Cybersecurity

Data Loss Prevention (DLP)

DLP refers to controls that detect or prevent sensitive information from leaving approved systems or being exposed inappropriately. In AI workflows, DLP must cover prompts, retrieved documents, outputs, logs, and integrations.

Reference ↗
Cybersecurity

Incident Response

Incident response is the process for detecting, triaging, containing, communicating, and learning from AI or cybersecurity incidents. AI deployments should define escalation paths before failures occur.

Reference ↗
Cybersecurity

Insecure Output Handling

Insecure output handling occurs when AI-generated outputs are trusted too much and passed into downstream systems without validation. This can create software, security, compliance, or business-process failures.

Reference ↗
Cybersecurity

Jailbreaking

Jailbreaking is an attempt to bypass a model’s safety or policy constraints through adversarial prompting. It is related to prompt injection but usually targets the model’s refusal or behavior rules directly.

Reference ↗
Cybersecurity

Model Supply Chain

The model supply chain includes datasets, pre-trained models, libraries, plugins, APIs, infrastructure, vendors, and deployment tools. Weaknesses anywhere in the chain can create security, reliability, or compliance risks.

Reference ↗
Cybersecurity

OWASP Top 10 for LLMs

OWASP’s Top 10 for Large Language Model Applications enumerates the most critical security risks specific to LLM-powered systems. It is the most widely referenced practitioner checklist for AI application security reviews.

Reference ↗
Cybersecurity

Prompt Injection

Prompt injection occurs when malicious or conflicting instructions are inserted into inputs so an LLM follows the attacker’s goal instead of the system’s intended rules. It is a major security issue for AI systems that read documents, browse content, or use tools.

Reference ↗
Cybersecurity

SAIF (Secure AI Framework)

SAIF is Google’s open conceptual framework for securing AI systems across the lifecycle, addressing model, data, and operational risks. It is one of the most widely cited industry frameworks for AI security alongside NIST and OWASP guidance.

Reference ↗
Cybersecurity

Sensitive Information Disclosure

Sensitive information disclosure occurs when an AI system reveals private, confidential, or restricted information through its output or logs. Controls include access management, data minimization, filtering, monitoring, and careful retrieval design.

Reference ↗
Cybersecurity

Training Data Poisoning

Training data poisoning happens when corrupted or malicious data enters a model’s training or tuning process. The result can be biased behavior, hidden vulnerabilities, or unreliable outputs.

Reference ↗
Cybersecurity

Zero Trust

Zero trust is a security approach that assumes no user, device, model, or system should be trusted by default. AI systems need zero-trust thinking because they often connect data, tools, identities, and automated actions.

Reference ↗

An AI operating model defines how an organization funds, builds, governs, deploys, monitors, and scales AI. It clarifies the roles of business teams, data teams, risk teams, product owners, and senior leadership.

Reference ↗
Strategy

AI ROI

AI ROI measures whether an AI initiative creates value net of data, infrastructure, talent, risk, adoption, and maintenance costs. Because many benefits are process-level, ROI should include productivity, quality, speed, risk reduction, and revenue impact.

Reference ↗
Strategy

AI Strategy

AI strategy connects business goals to AI-enabled capabilities, use-case priorities, data assets, talent, platforms, and governance. A strong AI strategy says what not to do as clearly as what to build.

Reference ↗

Reference ↗
Strategy

Build–Buy–Partner Decision

A build–buy–partner decision determines whether to develop AI internally, purchase a vendor solution, or collaborate with startups and platforms. The right choice depends on strategic differentiation, data sensitivity, speed, talent, and integration complexity.

Corporate Innovation Model

A corporate innovation model defines how a large organization explores, tests, funds, and scales new ideas. AI raises the importance of fast experimentation, responsible controls, external partnerships, and executive sponsorship.
